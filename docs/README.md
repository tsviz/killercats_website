## 📖 Documentation Structure

### Beginner Path
If you're new to the project, follow this path:

1. Read [Root README.md](../README.md) for overview
2. Review [Project Structure](./PROJECT_STRUCTURE.md) to understand organization
3. Follow [Development Guide](./DEVELOPMENT.md) to set up environment
4. Start with simple changes and refer to [API Reference](./API_REFERENCE.md) as needed

### Advanced Path
If you're experienced with ASP.NET Core:

1. Skim [Architecture Overview](./ARCHITECTURE.md) for design decisions
2. Review [API Reference](./API_REFERENCE.md) for components
3. Dive into code with [Project Structure](./PROJECT_STRUCTURE.md) as reference
4. Use [Troubleshooting Guide](./TROUBLESHOOTING.md) when needed

### Deployment Path
If you're deploying the application:

1. Review [Architecture Overview](./ARCHITECTURE.md) for infrastructure needs
2. Follow [Deployment Guide](./DEPLOYMENT.md) for your platform
3. Keep [Troubleshooting Guide](./TROUBLESHOOTING.md) handy
4. Set up monitoring per [Deployment Guide - Monitoring](./DEPLOYMENT.md#monitoring-and-maintenance)

## 🤝 Contributing to Documentation

### Reporting Documentation Issues

If you find errors or gaps in documentation:

1. **Check if issue already reported**: [GitHub Issues](https://github.com/tsviz/killercats_website/issues)
2. **Create new issue** with:
   - Document name and section
   - Description of issue
   - Suggested improvement (optional)

### Improving Documentation

To contribute documentation improvements:

1. **Fork the repository**
2. **Edit Markdown files** in `docs/` folder
3. **Follow existing style** and structure
4. **Test links** and code examples
5. **Submit pull request** with clear description

See [CONTRIBUTING.md](../CONTRIBUTING.md) for detailed guidelines.
